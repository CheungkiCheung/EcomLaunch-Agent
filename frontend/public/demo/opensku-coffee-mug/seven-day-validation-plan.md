# Sample Seven-Day Validation Plan — Compact Travel Coffee Mug

> Recorded demo fixture. Thresholds below are planning examples and should be replaced with targets derived from the operator's economics, channel, and risk tolerance.

## Day 1 — Lock the claims boundary

- List every proposed feature and performance claim.
- Mark each item as verified, estimated, or assumed.
- Remove any claim that cannot be demonstrated by the available sample.

## Day 2 — Run five problem interviews

- Recruit commuters who already carry coffee.
- Ask about the last real spill, cleaning frustration, and abandoned mug purchase.
- Record exact language; do not pitch the product during discovery.

## Day 3 — Test the physical protocol

- Measure weight, dimensions, and cup-holder fit.
- Run inversion, bag-motion, and hot-liquid handling tests.
- Capture an unedited result log with pass/fail outcomes.

## Day 4 — Build three message variants

1. Compact carry.
2. Demonstrated leak protocol.
3. Easy-clean lid.

Keep the product, price, audience, and traffic source constant so the message is the main variable.

## Day 5 — Run a small intent test

- Send the same qualified traffic allocation to each variant.
- Measure landing-page engagement and a meaningful intent event such as waitlist signup.
- Treat clicks as directional interest, not purchase demand.

## Day 6 — Review objections and economics

- Code interview and message-test feedback by theme.
- Add landed cost, fulfilment, payment fees, returns allowance, and target acquisition cost.
- Calculate the maximum tolerable acquisition cost before increasing spend.

## Day 7 — Decide

- **Proceed to pilot:** physical gates pass, one message wins clearly, and the economics retain the required margin.
- **Revise:** the problem is real but product performance or positioning is weak.
- **Stop:** the core promise fails testing or viable economics require unsupported claims.

Document the decision, evidence used, remaining assumptions, and the next falsifiable test.
